Tile extras ​

A tile whose flags have bit 0x01 carries extra data after its record (see World data): a u8 type, then that type's bytes. This page lists every type the 5.60 client's parser (TileExtra_Serialize, 0x15ce080) knows, in the direction the client reads them from the server (SEND_MAP_DATA 0x04 and SEND_TILE_UPDATE_DATA 0x05).

  • Which type a tile uses comes from its foreground item's action type in items.dat (0x15d1014, run when the foreground is set). If the server sends a type that doesn't match, the client reads the wrong bytes and the rest of the world is garbage.
  • Some fields exist only in the client's own saved copy of a world. They are marked not sent by the server; don't send them.
  • After the type's own bytes, items with a certain item flag have a common trailer. It is described on World data.
  • Numbers are little-endian. Strings are u16 length + bytes, with no terminator.

0x01 Door ​

Doors, the Main Door, portals and the Sungate: items with action type 2 (Door), 13 (Main Door), 26 (Portal) and 43 (Sungate). Created by 0x15d1014 for those action types.

From the server (the 0x04 world load and 0x05 tile updates both pass "from server"):

BytesFieldMeaning
u16 len + byteslabelthe text shown over the door (extra+0x28)
u8flagsextra+9. Bit 3 (0x08): locked. The client then checks whether you may use it (0x15b2a80) and shows `w<Locked> `` instead of the label if you may not

Not sent by the server: the client's own saved copy has three strings instead of one: extra+0x10, +0x28 (label), +0x40, then the u8. +0x10 is shown in place of the label when it isn't empty, so it is probably the destination (WORLD:ID) and +0x40 the door's id.

  • The label is drawn by the tile-info code (0x13002b4). Item 9358 (0x248e) never shows its label.
  • When the client writes a door that came from a server (only for its local copy) and the item isn't Gateway To Adventure (1682), Mystery Door (4718) or Mystery Portal (11136), it writes the destination if it has one, cut at :.

Read by 0x15ce080 case 1 (falls through to the u8 of case 0x42); shown by 0x13002b4.

0x02 Sign ​

Signs, tombstones, banners and markers: item action type 10. Created by 0x15d1014.

BytesFieldMeaning
u16 len + bytestextthe sign's text (extra+0x28), shown in a bubble by the tile-info code (0x13002b4, through 0x15b1de8)
u32valueextra+0xc. Not read by the sign display; gurotopia sends -1. Its meaning wasn't traced

For seven items the text goes to extra+0x40 instead and isn't shown as a sign: Path Marker (1684), Carnival Landing (1912), Gruesome Marker (4446), Objective Marker (4482), Hospital Chair (14678), Fashion Show Bouncer (15598) and Fashion Show Voting Box (15600) (0x15b17d0). For those it is probably an id the item uses.

When the client writes a sign it filters the text first (0x1585028).

Read by 0x15ce080 case 2.

0x03 Lock ​

Every lock (Small/Big/Huge Lock, World Lock, Diamond Lock, Guild Lock, ...): item action type 3. Created by 0x15d1014.

BytesFieldMeaning
u8flagsextra+9: the lock's settings bits
u32ownerextra+0xc: the owner's user id
u32countnumber of entries that follow
u32 × countaccessextra+0x80: user ids with access
u32(world version ≥ 12)extra+0x138; meaning not traced
u32(world version ≥ 13)extra+0x13c; meaning not traced

The world version is the u16 at the start of the world data (world+2). A tile update (0x05) uses the version of the world that is loaded.

  • Changing a tile away from its lock removes the lock's area (0x15aef40 → 0x1625994).
  • The Guild Lock (5814) is followed by the guild block described in the common trailer, without its first u8.

Read by 0x15ce080 case 3.

0x04 Seed ​

A planted tree: item action type 19 (seeds). Created by 0x15d1014 with the age 0 and 3 fruit.

BytesFieldMeaning
u32ageextra+0x5c: seconds since it was planted. The client keeps counting from here
u8fruitextra+0x60: how many fruit the tree has
  • The client adds the seconds that pass to the age by itself (0x15d0b24, run before every serialize and by 0x15d1a64).
  • The tile text (0x15b2604) shows the time left, the seed item's grow time (item+0xc4) minus the age, as "... to harvest", or `w(Punch to harvest) `` when it is ready.

Read by 0x15ce080 case 4 (switchD…caseD_4).

0x05 (no data) ​

Created by 0x15d1014 for item action type 30, with extra+9 = 2. No item in the 5.60 items.dat has that action type.

The switch in 0x15ce080 has no case for 5, so it carries no bytes of its own (only the common trailer, if the item's flag asks for it).

0x06 Mailbox ​

Mailbox, Blue Mailbox, Hacker's Dialog, Message in a Bottle, Message in a Diamond Bottle: item action type 33.

BytesFieldMeaning
u16 len + bytesstring 1extra+0x10
u16 len + bytesstring 2extra+0x28
u16 len + bytesstring 3extra+0x40
u8flagextra+9

The same four fields are read for every type that shares this code (6, 7, 0x0c, 0x0d). Reading also clears extra+0x58. The tile code in this range doesn't read the strings; they are probably filled only for the owner, and the byte probably tells whether something is inside (neither was traced).

Read by 0x15ce080 case 6 (shared with 7, 0x0c, 0x0d).

0x07 Bulletin board ​

Bulletin Board, Letter, Guestbook, Scroll Bulletin, Retinal Scan Data Repository (action type 34), and the Security Camera, Starship Security Camera and Pigeon (action type 50; created with extra+9 = 8).

Same layout as 0x06: three strings (extra+0x10, +0x28, +0x40) and a u8 (extra+9).

0x08 Dice block ​

Dice Block and Roshambo Block: item action type 36.

BytesFieldMeaning
u8valueextra+0x60: probably the face shown (the dice roll itself comes in TILE_APPLY_DAMAGE, 0x08)

Read by 0x15ce080 case 8 (switchD…caseD_8, shared with 0x10).

0x09 Provider ​

Things that produce an item over time (Cow, Chicken, ATM Machine, Science Station, Coffee Maker, Well, Tackle Box, ...): item action type 38.

BytesFieldMeaning
u32ageextra+0x5c: seconds since it was last collected; the client keeps counting
u32(only some items)extra+100, read only for the Winterfest Calendar - 2017 (5318), and for the Well of Love (10656) when the world version is above 16
  • The tile text (0x15b45d0) shows "Ready in ..." (the item's grow time, item+0xc4, minus the age) or "(`wPunch to collect``)".
  • For the Well of Love it compares extra+100 with the grow time / 60 and shows "(n/m)", so that value is probably how many times it has been used.

Read by 0x15ce080 case 9.

0x0a Achievement block ​

The Achievement Block (982): item action type 40. Created with extra+0x60 = 0x7f.

BytesFieldMeaning
u32valueextra+0xc (0 when created); probably the user id of the player whose achievement it shows (not traced)
u8achievementextra+0x60: the icon drawn. 0–127 picks a frame of game/amorkolg.rttex, a negative value a frame of game/amorkasd.rttex (renderer 0x11a9ee4)

Read by 0x15ce080 case 0x0a (u32, then the u8 of caseD_8).

0x0b Heart monitor ​

The Heart Monitor (1240): item action type 46.

BytesFieldMeaning
u32userextra+0xc: probably the user id of the player it tracks
u16 len + bytesnameextra+0x28: the player's name

The tile text shows the name and Status: Online, or `4Offline ``. Online comes from the tile's "on" flag (tile flags 0x40), not from the extra data.

Read by 0x15ce080 case 0x0b (u32, then the string of case 0x40); shown by 0x13002b4.

0x0c Donation box ​

Holiday Gift Box, Donation Box, Donut Donation Box: item action type 47.

Same layout as 0x06: three strings (extra+0x10, +0x28, +0x40) and a u8 (extra+9).

0x0d (mailbox layout) ​

Created for item action type 48. No item in the 5.60 items.dat has that action type.

Same layout as 0x06: three strings and a u8.

0x0e Mannequin ​

Mannequins (Mannequin, Holographic Mannequin, Snowtopian, the OMG/SAD/LOL/TROLL Mannequins, Shiny, Pearl and Diamond Mannequin, Sandtopian): item action type 49. Created with an AvatarData object (extra+0x98) that holds the clothes.

BytesFieldMeaning
u16 len + byteslabelextra+0x28: text, shown like a sign's (0x15b1de8 treats types 2 and 0x0e as signs)
u8flagextra+9
u32valueextra+0x58
u16 × 9clothesitem ids of the 9 clothing slots, copied into the AvatarData (+0x14), probably in the OnSetClothing order (hair, shirt, legs, feet, face, hand, back, head, charm). The tint is set to 0xb4b4b4ff
u32, u32(only if a slot holds Will of the Wild (5712) or Golem's Gift (10044), world version ≥ 4)ORed into AvatarData+0x28 and +0x2c; probably those items' extra state bits

The renderer (0x11a9ee4) draws the AvatarData on the tile.

Read by 0x15ce080 case 0x0e; AvatarData setters 0x14ce8f8, 0x14ce85c.

0x0f Bunny egg ​

The Bunny Egg (610): item action type 51.

BytesFieldMeaning
u32countextra+0x5c. The client doesn't age this type (0x15d0b24 skips it), so it is a plain counter, probably the eggs put in

Types 0x1b, 0x26, 0x27, 0x32 and 0x39 share this one-u32 code.

Read by 0x15ce080 case 0x0f (switchD…caseD_f).

0x10 Game block ​

The team items of the game blocks (Staging Platform, Game Block, Game Flag, Game Grave, Game Goal, Game Egg, ...): item action type 52. Created with extra+0x60 = 4.

BytesFieldMeaning
u8teamextra+0x60: the team the block belongs to. The touch code compares it with the player's team (avatar+0x26d) to decide whether the flag, goal or grave reacts. 4 (the default) is probably "no team"

Same code as 0x08.

Read by 0x15ce080 case 0x10; compared in 0x13002b4.

0x11 Game generator ​

The Game Generator (1660): item action type 53.

The switch in 0x15ce080 has no case for 0x11, so it carries no bytes of its own.

0x12 Xenonite crystal ​

The Xenonite Crystal (2072): item action type 54.

BytesFieldMeaning
u8flagsextra+9: probably the effects it turns on in the world (not traced)
u32valueextra+0x5c. Not aged by the client

Type 0x1a reads the same way.

Read by 0x15ce080 case 0x12.

0x13 Phone booth ​

Phone Booth (2208) and Transmutabooth (9170): item action type 55.

BytesFieldMeaning
u16 × 9clothes9 item ids, as in 0x0e. They are copied only if the extra has an AvatarData, which 0x15d1014 creates only for mannequins, so for these items the 18 bytes are skipped

Reading also stores the current tick in extra+0x58.

Read by 0x15ce080 case 0x13.

0x14 Crystal ​

The Red, Green, Blue, White and Black Crystal: item action type 56.

From the server:

BytesFieldMeaning
u16 len + bytestextextra+0x10; probably the crystal sequence (not traced)

Not sent by the server: only the client's saved copy adds the u32 count + u32 list of type 0x20.

Read by 0x15ce080 case 0x14 (then case 0x33, which reads nothing from a server).

0x15 Crime in progress ​

Crime In Progress (2302): item action type 57.

BytesFieldMeaning
u16 len + bytestextextra+0x10; probably the villain's name (not traced)
u32ageextra+0x5c: seconds; the client keeps counting
u8valueextra+0x60

Reading clears extra+0xc. The tile-info code shows something for this type (or for item 3528) through 0x15b1e40.

Read by 0x15ce080 case 0x15 (the string, then caseD_4, like a seed).

0x16 Spotlight ​

The Spotlight (2646): item action type 59.

No bytes. Reading only clears extra+0xc.

0x15ce080 case 0x16.

0x17 Display block ​

The Display Block (2946): item action type 61.

BytesFieldMeaning
u32itemextra+0xc: the item shown in the block. The renderer draws that item's icon on it (0x11a9ee4, item 0xb82)

Reading clears extra+0x58.

Read by 0x15ce080 case 0x17.

0x18 Vending machine ​

Vending Machine (2978) and DigiVend Machine (9268): item action type 62.

From the server:

BytesFieldMeaning
u32itemextra+0x58: the item for sale, 0 if none
i32priceextra+0xc. Above 0: World Locks per item. Below 0: that many items per World Lock

Not sent by the server: the client's saved copy adds a u32 stock (extra+0x5c) and a u32 (extra+100, probably the World Locks earned), and turns tile flags 0x40 and 0x200 on or off from them. When it writes a machine whose items-per-lock is more than its stock, it writes item 0.

The tile text (0x13002b4) shows Selling 2<item>` ... ` World Locks each` or ` per World Lock`, or `wOUT OF ORDER when the item or price is 0. Vending Hub - Checkout Counter (9270) doesn't show it.

Read by 0x15ce080 case 0x18.

0x19 Fish tank port ​

The Fish Tank Port (3002): item action type 63.

BytesFieldMeaning
u8flagsextra+9
u32countnumber of u32 values that follow
u32 × countvaluesextra+0x80; probably pairs of fish item id and weight (not traced)

Read by 0x15ce080 case 0x19 (u8, then the list of caseD_20).

0x1a Solar collector ​

The Solar Collector (3078): item action type 65. Created with extra+9 = 0x18.

BytesFieldMeaning
u8modeextra+9: bits 0x08 and 0x10 pick the text "Only works when planting", "Only works when splicing" or "Disabled"
u32chargeextra+0x5c: seconds of charge; the client keeps counting. Full at 86400 (one day)

The tile text (0x15b4298) shows Solar Collector, then n% charged (charge × 100 / 86400) or Fully charged!, then the mode.

Read by 0x15ce080 case 0x1a (same code as 0x12).

0x1b Forge ​

The Forge (3194): item action type 66.

BytesFieldMeaning
u32timeextra+0x5c: seconds. Unlike most types the client counts this one down to 0 (0x15d0b24), so it is probably the time left on the current job

Same code as 0x0f.

Read by 0x15ce080 case 0x1b.

0x1c Giving Tree ​

Item action type 67, the Giving Tree (3200). It grows a gift you can punch out.

BytesFieldMeaning
