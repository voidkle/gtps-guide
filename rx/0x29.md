PvE: the client's name for this type is `NET_GAME_PACKET_PVE_NPC`. It drives the PvE enemies kept by a manager at GameLogic+0x4d8. Each enemy is a 0x370-byte entry with an id at +0x2a8. Both sub-commands only work when the `proto` value from the login settings is at least 999999.
That value is the `proto=` key in the last argument of
[OnSuperMainStartAcceptLogonHrdxs47254722215a](/functions/OnSuperMainStartAcceptLogonHrdxs47254722215a), stored
at app+0xc08 (`0x1ba4ab4`); gurotopia sends the client's own protocol number there (around 225). So with a
normal `proto` the client ignores this packet entirely.

| Field | Used as |
|---|---|
| `buildRange` | the sub-command: 0 or 1 |
| `itemID` | the enemy id (0) |
| `particleID` | the hit amount, as a float (0) |
| `posX`, `posY` | where the hit came from, for the knock-back direction (0) |

### Sub-commands
`buildRange` selects what happens:

| Value | Effect | Fields used |
|---|---|---|
| 0 | Enemy `itemID` is hit. It flashes for 200 ms (+0x2e4, read back by `0x14b31e4` and `0x14b7394`). It also stores `particleID` minus a value from its current form's stats (never below 0; probably the damage after armor) and the direction from `pos` to the enemy, but nothing in 5.60 reads those two back: only the enemy's copy function (`0x14beae8`) touches +0x2e8/+0x2ec. | `itemID`, `particleID`, `posX`, `posY` |
| 1 | Toggles a PvE phase (`sub_14ac2a8`). Going in arms a 10-second timer and enables 14 slots; going out disables them and arms a 300 ms timer. On a change it flips flag 0x40 on a special world tile (world+0x4a0). Only when the manager's flags +0xb8c and +0xb8d are set. | |

Any other value does nothing.
