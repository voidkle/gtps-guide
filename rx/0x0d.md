Adds items to or removes items from your inventory. The amounts are in the type bytes: `jumpCount` is the
amount to remove, `buildRange` the amount to add. `jumpCount` decides which one happens.

| Field | Used as |
|---|---|
| `itemID` | the item |
| `jumpCount` (byte 2) | amount to remove. If it's 0, the packet adds instead |
| `buildRange` (byte 3) | amount to add (only read when `jumpCount` is 0) |

`netID` is not read: it always applies to you.

### Sub-commands

| `jumpCount` | Effect | Fields used |
|---|---|---|
| 0 | `AddItem(itemID, buildRange)`. The stack is capped at the item's max (usually 200), and at 477 different items it logs "inventory overload" and adds nothing. If the item's action type is 112, it's also put in quick slot 1, selected, and the inventory's `OnItemClicked` runs for it. The inventory UI refreshes if the number of different items changed | `itemID`, `buildRange` |
| 1–255 | `RemoveItem(itemID, jumpCount)`. Removing more than you have logs "Error, can't remove all %d items of type %d from inventory" and removes what's there. When the stack reaches 0 the item and its quick slots are cleared and the inventory UI refreshes | `itemID`, `jumpCount` |

Some items can't be added or removed this way at all (the client's `0x156e5d0` check), and the packet then does nothing.

```c
case 0x0d:
    if (pkt->jumpCount == 0) {
        int before = inventory->itemCount;                     // self+0x238

    } else {
        if (inventory->RemoveItem(pkt->itemID, pkt->jumpCount) == 0)
            RefreshInventoryUI();
    }
    break;

int PlayerItems::RemoveItem(int id, int amount)               // 0x1595cb8
{
    if (CantTouch(id)) return 0;
    Item *it = Find(id);
    if (!it) return 0;
    if (it->amount < amount) {
        LogError("Error, can't remove all %d items of type %d from inventory", amount, id);
        amount = it->amount;
    }
    if (it->amount - amount == 0) { ClearQuickSlotsFor(id); items.erase(it); return 0; }
    return it->amount -= amount;
}
```
