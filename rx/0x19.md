The client never handles this type; it **sends** it. When one of its integrity checks fails, it reports
the failure to the server with `0x137c374`. The checks compare values such as the physics constants with
copies the client keeps elsewhere. There are 24 call sites, in the physics, landing, movement and avatar code
and in `OnSetPos` and `OnSetClothing`. Each passes a code from 1 to 28; a few codes are used at two sites. Most of them also
store the code at avatar+0x258, which every [PING_REPLY (0x15)](./15-ping-reply) repeats in byte 3, and
send at most once per cooldown (avatar+0xfc).

| Field | Value |
|---|---|
| `type` | 0x19 |
| `itemID` | the check's code (for example 25 from `OnSetPos`, 28 from `OnSetClothing`) |
| `targetNetID` | an extra value from the call site; 0 for almost all of them |
| `posX`, `posY` | a vec2 from the call site; what it holds differs per check (`OnSetPos` passes stack slots it never fills) |
| `speedX`, `speedY` | a second vec2 from the call site |
| everything else | 0 |

Sent reliable, without extra data. A server can log these to spot modified clients; gurotopia ignores them.

```c
void ReportIntegrityFail(GameLogic *self, vec2 *a, vec2 *b, int code, int extra)   // 0x137c374
{
    packet h = {0};
    h.type = 0x19;
    h.itemID = code;
    h.targetNetID = extra;
    h.posX = a->x;  h.posY = a->y;
    h.speedX = b->x; h.speedY = b->y;
    SendPacket(4, &h, 56, NULL, GetApp()->client->peer, 1);   // 0x157ee8c
}
```

<small>Sender: `0x137c374` in the 5.60 arm64 client; callers include `0x12f5158` (OnSetPos), `0x12f59cc` (OnSetClothing), `0x12faa1c`, `0x13063d8`, `0x130ff58`.</small>
