The client never handles this type; it **sends** it, when your own avatar lands on a tile whose item has
action type 135. The only such item in the 5.60 items.dat is the **Ghost Block** (10056). The packet names
item 3728, the **Ectoplasm Sample**, so the server probably gives one to the player.

| Field | Value |
|---|---|
| `type` | 0x2e |
| `itemID` | 3728 (Ectoplasm Sample), a constant |
| `tileX`, `tileY` | the Ghost Block under you (tile+0x54, +0x55) |
| everything else | 0 |

Sent reliable, without extra data. It isn't sent while the avatar flag at +0x179 bit 1 is set (not traced).
The check runs in the landing code `0x12f9fd0` (called from `0x130691c`). It sits next to the checks for
death spikes (action type 6) and the integrity checks that send [0x19](./19-app-integrity-fail), so it runs
on every landing on such a tile.

```c
// in the landing code 0x12f9fd0, after the collision below the avatar found `tile`
else if (GetItemInfo(tile)->actionType == 135 && !(avatar->flags_179 & 2))
    SendStepOnTileMod(GetGameLogic(), tile, 3728);                       // 0x13816a0

void SendStepOnTileMod(GameLogic *self, Tile *tile, uint item) {         // 0x13816a0
    if (!tile) return;
    GameHeader h = {};
    h.type = 0x2e;
    h.itemID = item;
    h.tileX = tile->x;  h.tileY = tile->y;
    SendGamePacket(4, &h, 0x38, NULL, GetApp()->client->peer, 1);       // 0x157ee8c
}
```

<small>Sender: `0x13816a0`, called from `0x12f9fd0` in the 5.60 arm64 client.</small>
